# Security policy

## Supported version

Security fixes are applied to the latest commit on `main`. Deployments should track a reviewed release or current `main` and rebuild regularly so base-image and dependency fixes are included.

## Report a vulnerability privately

Do not open a public issue for a suspected vulnerability. Use [GitHub private vulnerability reporting](https://github.com/Rionlyu/rionlyu-tech-blog/security/advisories/new) instead.

Include the affected route or component, reproduction steps, impact, and any suggested remediation. Do not include real contact submissions, credentials, tokens, or other personal data. You may use obvious test data against a deployment you control.

Reports about the configured contact provider should also identify whether the behavior occurs in this application or in the external provider. Availability incidents and ordinary bugs can use the public issue tracker when they do not expose sensitive information.
